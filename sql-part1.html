What Is SQL & Why Databases Matter

Beginner-friendly · Databases · SQL Basics

Every app you use — Instagram, Spotify, your university's student portal — stores its data somewhere, and almost always queries it with SQL. This series starts from zero: no prior database experience needed. By the end of Part 1, you'll understand what a relational database actually is, and you'll write your first query.

📊 Why not just use a spreadsheet?

A spreadsheet works fine for a small personal list. But once data gets large, gets shared across many users, or needs to stay consistent while dozens of people update it at once, spreadsheets start to break down.

Spreadsheets

Slow at scale, no real way to enforce rules ("age must be a number"), painful to link related data across sheets, and risky with multiple simultaneous editors.

Relational databases

Built to handle millions of rows, enforce data rules automatically, link related tables cleanly, and handle many simultaneous reads/writes safely.

A database is just organized, persistent storage for data. A relational database organizes that data into tables — think structured spreadsheets that can be precisely linked to one another.

🧱 Tables, rows, and columns

A table stores one type of thing — say, students. Each row is one specific student. Each column is one property every student has, like name or major.

A real application usually has many tables — students, courses, enrollments — each storing one kind of entity, connected to the others through shared ID columns. We'll cover exactly how those connections work when we get to joins later in the series.

🗣️ So what is SQL, exactly?

SQL stands for Structured Query Language. It's how you talk to a relational database: asking it to retrieve, add, update, or remove data. The key thing that makes SQL different from a typical programming language is that it's declarative — you describe what data you want, not how to go get it. The database figures out the "how" for you.

Declarative vs. imperative

In a language like Python, you'd write a loop: check each student one by one, and collect the ones majoring in EEE. In SQL, you just state the result you want, and the database handles the retrieval internally — usually far more efficiently than a hand-written loop would.

🔍 Your first query: SELECT

The most common SQL statement is SELECT — it retrieves data from a table. Here's the anatomy of a simple query:

SELECT name, gpa
FROM students
WHERE major = 'EEE';
SELECTwhich columns
FROMwhich table
WHEREwhich rows

Read it almost like English: "give me the name and gpa, from the students table, where the major is EEE." Running this against our example table above would return just Buse and Elif's rows.

Want every column instead of naming them one by one? Use SELECT * — the asterisk means "all columns."

💡 Final takeaway

Relational databases organize data into linked tables instead of scattered spreadsheets, and SQL is the declarative language used to ask them questions. You now know what a table is and how to write a basic SELECT query. In Part 2, we'll go further with filtering and sorting — comparison operators, ORDER BY, and LIMIT — to get exactly the rows you want, in the order you want them.
