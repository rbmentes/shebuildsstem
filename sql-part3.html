PART 3

Aggregating Data

Beginner-friendly · GROUP BY · Aggregate Functions

So far we've filtered and sorted individual rows. But a lot of real questions are about summaries: "how many students per major?" or "what's the average GPA?" That's what aggregate functions and GROUP BY are for.

🧮 Aggregate functions

An aggregate function takes many rows and collapses them into a single value:

FunctionReturns
COUNT()number of rows
SUM()total of a numeric column
AVG()average of a numeric column
MIN() / MAX()smallest / largest value
SELECT COUNT(*) AS total_students, AVG(gpa) AS average_gpa
FROM students;

Used alone like this, an aggregate collapses the entire table into one row of summary numbers.

🗂️ Grouping rows: GROUP BY

GROUP BY is where aggregates get really useful — it splits your rows into groups first, then runs the aggregate function separately per group.

SELECT major, COUNT(*) AS student_count, AVG(gpa) AS avg_gpa
FROM students
GROUP BY major;

This gives you one row per unique major, each with its own student count and average GPA — instead of one number for the whole table.

The rule to remember

Every column in your SELECT list must either be inside an aggregate function, or listed in GROUP BY. SQL needs to know exactly how to collapse every non-aggregated column, and it can't guess.

⚖️ WHERE vs. HAVING

WHERE

Filters individual rows before grouping happens. Cannot reference an aggregate function like COUNT().

HAVING

Filters groups after aggregation happens. Built specifically to filter on aggregate results.

SELECT major, COUNT(*) AS student_count
FROM students
GROUP BY major
HAVING COUNT(*) > 5;

This returns only majors with more than 5 students. Trying to write WHERE COUNT(*) > 5 instead would throw an error — at the point WHERE runs, the counts don't exist yet.

🔢 Putting it together

SELECT major, COUNT(*) AS student_count, AVG(gpa) AS avg_gpa
FROM students
WHERE year = 4
GROUP BY major
HAVING AVG(gpa) > 3.5
ORDER BY avg_gpa DESC;

Reading top to bottom: filter to 4th-year students, group by major, keep only majors averaging above 3.5 GPA, then sort by that average — a realistic query you might actually write on the job.

💡 Final takeaway

GROUP BY splits rows into buckets, aggregate functions summarize each bucket, and HAVING filters on those summaries — WHERE still handles filtering the raw rows beforehand. In Part 4, we'll connect data that lives across multiple tables using JOIN.
