Subqueries & CTEs

Beginner-friendly · Subqueries · WITH Clause

Sometimes one query needs the result of another query first. That's what subqueries and CTEs (Common Table Expressions) are for — writing a query inside a query, so you can build up complex logic step by step.

📦 What is a subquery?

A subquery is a SELECT statement nested inside another query, usually wrapped in parentheses. It runs first, and its result gets used by the outer query.

SELECT name, gpa
FROM students
WHERE gpa > (SELECT AVG(gpa) FROM students);

The inner query calculates the average GPA across all students; the outer query then finds everyone above that average. Without a subquery, you'd need two separate queries and to manually plug one result into the other.

📍 Where subqueries can live

LocationExample use
Inside WHERECompare a column against a calculated value
Inside FROMTreat a query's result as a temporary table to query further
Inside SELECTCompute a per-row value using a related query
SELECT s.name,
  (SELECT COUNT(*) FROM enrollments e WHERE e.student_id = s.student_id) AS course_count
FROM students s;

This adds a computed course_count column, calculated with a mini-query for every student row.

📝 Common Table Expressions: WITH

A CTE lets you name a subquery upfront using WITH, then reference that name later in your main query like it's a regular table.

WITH high_achievers AS (
  SELECT * FROM students WHERE gpa > 3.7
)
SELECT major, COUNT(*) AS count
FROM high_achievers
GROUP BY major;

Everything the CTE does, a subquery could also do — but the CTE reads top-to-bottom like a set of clearly labeled steps, instead of a query nested inside a query inside a query.

⚖️ Subquery vs. CTE — which to use?

Subquery

Fine for a single, simple, one-off calculation used in just one place.

CTE

Better for anything complex, reused more than once, or when readability matters — which, honestly, is most real queries.

You can chain multiple CTEs

Separate several WITH blocks with commas to build a readable pipeline: first CTE filters, second CTE aggregates the first, and your final query reads from the second — each step named and easy to follow.

💡 Final takeaway

Subqueries and CTEs let you break a complex problem into smaller, named steps — a query that answers a question using the answer to another question.
