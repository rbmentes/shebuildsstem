PART 4

Joins

Beginner-friendly · JOIN · Relational Data

Back in Part 1, we mentioned that real databases split data across multiple linked tables instead of cramming everything into one. JOIN is how you bring that split data back together in a single query.

🧩 Why split data into tables at all?

Imagine a single giant table with every student's name repeated on every course they're enrolled in. Update that student's name once, and you'd need to update it in dozens of rows — miss one, and your data is now inconsistent.

Instead, relational databases keep one row per real-world thing, and use ID columns to reference related data in other tables:

students
student_id, name, major
enrollments
enrollment_id, student_id, course_name

Here, enrollments.student_id points back to a row in students. This link is called a foreign key.

🔗 INNER JOIN

An INNER JOIN combines rows from two tables where the join condition matches on both sides — rows without a match on either side are left out entirely.

SELECT students.name, enrollments.course_name
FROM students
INNER JOIN enrollments
  ON students.student_id = enrollments.student_id;

This returns one row per enrollment, each paired with the matching student's name — but only for students who actually have at least one enrollment.

↔️ LEFT JOIN and RIGHT JOIN

LEFT JOIN

Keeps every row from the left table, filling in NULL for unmatched right-side columns.

RIGHT JOIN

Keeps every row from the right table, filling in NULL for unmatched left-side columns.

SELECT students.name, enrollments.course_name
FROM students
LEFT JOIN enrollments
  ON students.student_id = enrollments.student_id;

This version keeps every student, even ones with zero enrollments — their course_name just shows up as NULL.

Which one should you reach for?

INNER JOIN is the most common default. Reach for LEFT JOIN specifically when you want to know about rows with no match — like "which students have never enrolled in anything?" RIGHT JOIN is rarely used in practice, since you can usually just swap table order and use LEFT JOIN instead.

📐 A quick mental model

Join typeWhat you get
INNER JOINOnly rows that match in both tables
LEFT JOINAll left-table rows, matched right-table data or NULL
RIGHT JOINAll right-table rows, matched left-table data or NULL

Every join starts with an ON clause specifying exactly which columns should match — almost always a foreign key on one side and the corresponding ID on the other.

💡 Final takeaway

Joins let you reunite data that's deliberately split across tables, and choosing the right join type — INNER for strict matches, LEFT/RIGHT to preserve unmatched rows — depends on exactly which rows you want to keep.
